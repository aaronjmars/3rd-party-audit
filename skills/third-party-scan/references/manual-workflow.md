# Manual workflow

Use this only when `scripts/scan.py` cannot run (no Python, blocked network, or a flow the scanner does not cover). It is what the script does, step by step.

1. Read `GET https://whogetsmydata.com/api/v1/websites/{domain}`. The [API](https://whogetsmydata.com/api) needs no key and returns the latest report, scan time, method, third parties, services, evidence levels, and limitations. It files `www.example.com` under `example.com`. Inspect the actual JSON fields before extracting them.
2. If no report exists or it is too old for the question, send one `POST https://whogetsmydata.com/api/v1/scan` with `{"url":"domain"}`. For a named path, use `{"url":"https://domain/path","page":true}`. A site checked in the last 60 minutes comes back from the database instead of being scanned again. A 202 response means the scan is still running. A client timeout also does not prove failure: for a domain scan, check `GET /websites/{domain}` later and compare `scan_id` and `checked_at` before considering another POST; for a page scan, use the returned scan ID with `GET /scans/{id}`. Scans can take minutes. Respect the rate limits: 120 reads per 10 minutes and 50 scans per 10 minutes per IP; a 429 carries `Retry-After`. A recent cached response is not a new scan.
3. Check `representative`, `method`, timestamp, pages covered, and reported limitations. A bot-block page, source-only scan, or public homepage does not establish what an authenticated user receives.
4. Inspect `third_parties[]` (`host`, `loaded`, `policy_only`) and `services[]` (`name`, `evidence_level`, `load_context`, `hosts`, `pages`). An `evidence_level` describes how the scanner identified a service, not whether the browser requested it. `observed` may mean an HTML tag or header; `detected` may mean a signature match. A CSP-only service is `inferred`, with `load_context: csp`.
5. For exact request evidence, download the report's `evidence.download_url` and inspect `evidence.json` in the ZIP; its SHA-256 must match `evidence.sha256`. Its `requests[]` records have `url`, `type`, `third_party`, `found_in`, and sometimes `browser_stages`. `found_in: browser` proves a browser request in the scanned flow; `static_html` or `script_content` is a reference; `csp_header` is permission only. The request `type` can reflect the embedding tag rather than the response bytes. Before calling a `script` request executable JavaScript, check its response Content-Type or body when feasible. Mark unverified MIME types as unknown. Group hosts by vendor, but retain the request URL and provenance for each security-relevant candidate.

If the API is unavailable, use a browser capture and say which flows were tested; do not fabricate a complete inventory.
